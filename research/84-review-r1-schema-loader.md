## Findings

1. **should — convention designs ranked above authority designs (`research/designs/cv.csv:4-5`).** research/80 §3 says convention is "always ranked last". The cv family is ranked 1 authority, 2 authority, **3 convention (ats-strict), 4 convention (academic), 5 authority (dach), 6 authority (editorial)**. Fix: re-rank to authority 1-4 and convention 5-6. Alternatively, record an explicit ruling that fitness ordering overrides evidence ordering. The doctype default remains a fitness pick regardless (§2D), so the reorder costs nothing. Nothing enforces this today, so add a `test_designs` assertion: within a family, Rank must be monotone in class order.

2. **should — mis-classified evidence, `research/provenance/seed-designs.csv` rows `cv-dach-tabular:1` and `cv-editorial:1`.** Both are tagged `authority`, and the cited source is a Typewolf *font-pairing page*. §3 lists Typewolf as a pairing source. A pairing page says nothing about a tabular Lebenslauf layout or an editorial CV. The fetched page cannot support the claim, which breaks R-a ("cite a source only for what a fetched copy says") and honest attribution. Fix: downgrade both to `convention`, with a blank source and `Fetch` blank or consistent. Or cite a source that actually covers the layout: for DACH, a fetched secondary that quotes DIN 5008, or a fetched Bewerbung guide. Also, `cv-us-uk-designed` claims "Harvard-OCS" in its Best For, but only Butterick is cited. Either drop the "Harvard" claim or cite it.

3. **should — `ranked` used for editorial recommendations (`research/provenance/typefaces-ranked-pairings.csv`, 7 rows, e.g. `typefaces:lib-alegreya-alegreya-sans:3`, `lib-libre-baskerville-libre-franklin:3`, `lib-eb-garamond-cabin:3`).** They are tagged `Evidence Class=ranked`, but the metric is "Typewolf suggested pairing (ordinal not numeric)" and Rank Value is blank. §2C and research/80 require ranked rows to carry a metric **and a value**. §3 defines ranked as a public usage/popularity metric, and a "suggested pairing" is an editorial recommendation, not a count. The Rank Value blank passes only because no test enforces it. Fix: re-class these 7 to `authority` (publisher/curator-documented pairing), or drop them. Add the ranked ⇒ non-empty Rank Value check to `test_provenance.py`.

4. **should — convention rows carry `Fetch=search-corroborated` with no source (17 rows in seed-designs.csv).** Nothing was searched, and there is no URL or source name. `search-corroborated` implies a source exists. Fix: allow a blank Fetch for convention, or add a `none` enum value. Also, `Retrieved` is set on rows that have no retrieval.

5. **should — the 19 doc-reasoning and 15 doc-styles rows have no provenance, and neither do 8 palettes and 13 typefaces (the safe/OS stacks).** Plan §2C says every row of designs/palettes/typefaces/doc-styles/doc-reasoning needs ≥1 provenance row or exactly one convention row. Only designs and the new library batches are covered (P1.3b backfill is not done). Any test for this rule will fail on the current base until the backfill lands or the rule is scoped. Also, the type-scales provenance covers only the 9 new ratio families (32 of 77 rows lack it). The plan's §2C list omits type-scales, but `Table` allows it. Decide whether the rule applies to it.

6. **advisory — `designs.Rank` has no int/contiguity enforcement in the manifest.** The plan says "int, contiguous 1..N per family". The manifest has no typing for it. Currently all values are valid. Enforce it in `test_designs.py`. Also confirm that `prov_key` matches `<Table>:<Row Key>:<n>`. All 147 do today, but nothing checks it.

7. **advisory — `LIBRARY_INPUTS_ENABLED` / `PROVENANCE_INPUTS_ENABLED` are hand-edited one-line lists.** The comments above them say "left EMPTY on purpose" and "Today that is only the seed file", which is now stale. Both are simple to fix: update the comments and wrap the lists. There is also a drift risk: a provenance batch can be enabled while its library batch is not (or the reverse). Add a check that every enabled provenance Row Key exists.

8. **advisory — `build-manifest.py` must be run from `skill/document-design-intelligence/` (relative `data\schema-manifest.json` path).** Running it from the repo root fails with FileNotFoundError, unlike `load-base.py`, which anchors on `__file__`. Anchor it the same way. `RESUME.md` should say which directory to run it from.

9. **advisory — the `ens-social → poster` mapping (research/26 and `make_brand_kit.FAMILY_HINT`).** This is defensible: the plan's 16 families have no social-image family, and poster (a single-canvas promotional item) is the closest. It is harmless in base, because ens rows are excluded. The risk is that once `designs` list per family, a brand `social` doctype will offer print-poster archetypes (bleed, large-format print) that don't fit an image. Recommend keeping `poster`, but note in the design's Not For that it is not a screen or social asset, or reconsider a `social` family in a later version. All other mappings are correct (brochure-flyer-* → flyer, slide-deck-* → deck, ens-note-interne → memo, ens-formulaire → form, ens-slides → deck).

10. **advisory — single-design families (15 of 16 families with 1 design, all convention).** Rank is trivially 1, and the plan's floor is 5 and the target 8-10. This is expected for a seed. Note that "ranked" behaviour cannot be exercised on those families yet.
