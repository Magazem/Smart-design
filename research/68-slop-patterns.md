# A1 — AI-slop pattern research across document types

Externally sourced failure patterns, one row per pattern. "Detection" says whether a mechanical
check is plausible in `preflight.py` (docx/pptx/pdf property or text inspection) or whether it
requires judge-level visual/semantic review. Every row cites a URL actually fetched via WebSearch/
WebFetch this session. A rule with no external source is tagged `CONVENTION` per
`feedback-refuse-unverifiable-attribution` — none needed here; all 11 seed patterns found at least
one citable source.

## Already encoded — do not duplicate

Before adding rules, checked what the skill's data already carries:

- **`doc-reasoning.csv` → Anti-Pattern Tokens** (per doc_category) already lists: `multi-column`,
  `text-box`, `icon-only-skill-bar`, `photo`, `graphic-timeline`, `color-coded-sections`,
  `gradient`, `emoji`, `low-contrast-text`, `gradient-banding`, `stock-photo-cliche`,
  `color-coded-field-meaning`, `rounded-card`, `color-coded-line-items`, `dense-paragraph-slide`,
  `spaghetti-chart`, `photo-heavy`, `3d-chart`, `color-coded-totals`.
- **`doc-styles.csv` → Checklist** already carries positive rules for: single-column enforcement,
  weight/size-based emphasis instead of colour, no icon-only skill bars, no photo unless region
  requires it, photocopy-safe fields (underline not box), no fills/gradients on forms/reports,
  header-and-total table rules with no zebra, 6×6 heuristic + high contrast for decks, fold-aware
  layout for print marketing, one accent reserved for stat callouts on infographics.
- **Already fully covered by the above, so excluded from new rows below**: `emoji` (token exists on
  6 of 12 doc_categories already) and the *boxed invoice cell* half of Odoo-clone grids (the
  `form-grid-underline` style's Checklist already says "Underline fields, do not box them" — the gap
  is that there's no explicit anti-pattern *token* naming it, see row below).
