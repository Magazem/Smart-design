# Proposal — header treatment + colour use recode under research/82a-general.md

Fresh recoder (never coded proposal before, and did not open any corpus/agreement/second-coder
file for this family). Source: `research/designs-evidence/proposal-items-ms.csv` (7 rows,
Microsoft-templates corroboration corpus — not a ranked corpus, recoded for completeness per the
orchestrator's task). Procedures: `research/82a-general.md` §A (header treatment) and §B (colour
use), read with `research/82a-clarifications-1..5.md`, principally C13 (report/whitepaper/proposal
are coded from the cover; here the single `preview_url` thumbnail per item IS the cover — a
`.webp` render of the document's page 1, used directly with no PDF rendering, per the task's
instruction), C17/C18 (fill = any area L≤0.90 incl. gradients; band requires the fill to sit
directly behind the title's own glyphs), and C20 (repeated decorative motifs vs. genuine elements,
editor/UI artefacts ignored). Because the family's boundary is `none` (§A.1's own table), every
header test is decided using the header block's own extent, not a following boundary element.

Thumbnails downloaded with `curl` (browser user-agent) to `research/designs-evidence/tmp-rprc/proposal/`
(scratch, deleted at the end of this task), converted from `.webp` to `.png` with Pillow (all 7 load
at native 400×519 px). Pixel measurements taken with `analyze.py` / `huescan.py` copied into that
same scratch directory from `research/designs-evidence/tmp-invrc/` (stdlib `colorsys`, same HSL
convention as the rest of 82a work): a 20×20 background-grid sampler, region/point samplers, and a
stride-3 hue scan bucketing S≥0.20 & 0.12≤L≤0.90 pixels into 10°-wide bins with area-share. Text
block boundaries (title, meta, rules) were found by thresholding grayscale rows/columns for dark
(or, on dark backgrounds, light) pixels and reading off the resulting bounding boxes. All
coordinates below are pixel coordinates in the 400×519 preview.
