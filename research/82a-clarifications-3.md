# research/82a — Clarifications round 3 (orchestrator, 2026-09-24)

Raised by the report L3 coder (research/designs-evidence/report-corpus-l3.md §R.5).

C13 **Cover-page families (report, whitepaper, proposal).** Page 1 is a cover, so §4's "code page 1"
    cannot yield body features. Code `header treatment`, `heading class` and `colour use` from the
    COVER; code `columns`, `body class`, `rules/boxes` and `density` from the FIRST RUNNING-TEXT PAGE
    (first page with >=250 words of running text). Record both page numbers per item. This is the
    coder's own practice in report-corpus-l3.md and is adopted as written.
C14 **A3 on covers.** A3 (text over busy fill) applies to running text and to any text block of 3+
    lines. A cover title/display line set on a photo is NOT excluded by A3, but it must pass A6
    contrast by C9 (sample, >=4.5:1 for text under 24pt, >=3:1 for display text >=24pt, the WCAG
    large-text threshold). Re-check the 14 ARC items' covers under C14 and log any change.
C15 **Corpus-size floor counts on-topic items only.** A catalogue page listing N cards of which
    fewer than 10 belong to the family is corroboration-only (poster MS: 5 of 10). research/82 §10's
    item counts were page totals and are superseded by the on-topic count.
C16 **Non-discriminating identity feature.** If one identity feature takes a single value across
    every admissible item of a family (report: header = image-hero 14/14), it is reported and
    kept; archetypes are then effectively 3-feature for that family. No coarsening is triggered by it.
